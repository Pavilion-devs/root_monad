Keep the context.
Connect your tools.

This developer preview opens an existing project. The owner dashboard runs on your computer; your signing key is never included in the website.

Build the frontend

From the portable-memory project folder:

npm --prefix frontend/ui ci
npm --prefix frontend/ui run build

Explore an isolated workspace

.mcp-venv/bin/python ops/dashboard_demo.py

The preview creates separate, disposable local identities and clearly labeled example records. It makes no model or blockchain calls.

Open the existing hosted project

.venv/bin/python ops/dashboard.py --hosted

This uses the existing Mac Keychain-protected owner configuration for the Monad testnet project. Open the private connection link printed in the terminal. Do not share it.

Use a developer-kit project

With its memory service already running:

.mcp-venv/bin/python ops/dashboard.py --state /path/to/workspace

Use that project's generated connections/claude.json or connections/codex.toml to connect a compatible assistant. The local kit uses a signed log, not Monad.

Try a handoff

  1. Ask one configured assistant to read current project memory.
  2. Ask it to propose a useful decision, with its source.
  3. Review the exact change in the dashboard and explicitly accept it.
  4. Open your other connected assistant and ask for the latest accepted context.

New hosted projects, browser wallet onboarding, and automatic app grants are not included. See FRONTEND.md, DEVELOPER_KIT.md, and V0_DESIGN.md in the repository for setup and trust boundaries.
